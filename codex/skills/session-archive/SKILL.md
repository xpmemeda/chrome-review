# 会话归档

把长会话整理成用户可直接阅读、也足以让其他 agent 核对后继续工作的持久记录。归档文件是事实和上下文的载体，不要求创建新任务，也不绑定固定目录结构。

## 工作模式

- **新建归档**：把当前会话写入用户指定的新文件。
- **追加归档**：在已有归档末尾追加一条新的自包含记录，保留旧内容不变。
- **读取继续**：读取用户指定的归档，恢复目标、约束和现场，核对变化后继续工作。

记住当前会话实际读取并用来恢复上下文的文件，称为“来源归档”。仅被提及但未读取的文件不是来源归档。

## 写入前确定文件与模式

写入之前先解析用户本轮是否已经明确指定目标文件和“追加/新建”模式，不重复询问已经明确的选择。

- 当前会话从来源归档恢复，用户再次要求归档但没有明确模式时，**必须先询问**：追加到该来源归档，还是写入新文件。询问时给出来源归档的绝对路径；选择新文件时一并取得或确认新路径。在用户回答前不写文件。
- 当前会话不是从归档恢复，用户已指定文件但未说明模式：文件不存在则新建；文件已存在则先询问追加还是另选新文件，不覆盖。
- 用户未指定文件时，询问目标路径。可根据当前仓库建议 `<仓库根目录>/.codex/archives/<任务名>.md`；无仓库时建议 `<当前工作目录>/outputs/archives/<任务名>.md`，但由用户确认。
- 用户明确要求追加到某文件或另存某文件时直接采用。除非用户明确要求重写，否则不覆盖或重排已有归档。

路径必须明确到文件。创建新文件时可以创建缺失的父目录；目标路径属于其他任务、是目录、无法读取，或格式明显不适合安全追加时，停止并说明问题。

## 归档内容

按 [references/archive-template.md](references/archive-template.md) 组织记录，省略不相关部分。内容服务于人类回顾和 agent 接手，而不是逐字转录聊天。

1. 从可见对话和已有资料恢复原始目标、最新修正、完成标准、用户约束及仍有效的授权。区分用户决定、agent 建议和未知事实。
2. 读取适用的 `AGENTS.md`、已有归档及任务状态文件。关键事实缺失时再按需回查可用历史；找不到就标“未知/待确认”，不假装完整回顾。
3. 对相关仓库做有边界的只读核对：路径、分支、HEAD、工作区改动、已有验证结果。归档本身不授权新增测试、提交、stash、重置、推送或清理现场。
4. 有远程机器或长任务时，读取 [references/remote-state.md](references/remote-state.md)。记录连接方式、工作目录、进程标识、日志和最后观察时间；无需为了归档重新连接所有机器。
5. 保存关键决策、失败尝试、被取代的结论、已完成/已验证/未验证状态及证据位置。不能为了缩短摘要而丢掉会影响后续判断或导致重复踩坑的失败记录。
6. 记录归档时间、时区、源任务标识（若可获取）和本条记录的来源范围。文档更新时间不能冒充事项发生时间。
7. 列出少量可执行的下一步，第一步注明对象、位置、动作和判据。

会话涉及推理优化、性能调优或工程实验时，必须读取 [references/optimization-experiments.md](references/optimization-experiments.md)，逐项归档优化改动、实验条件、实际数据、有效性和最终去向。该规则是归档内容的定向增强：仍将目标、当前状态、决策、现场和下一步作为归档主线，不把归档文件退化成只有 benchmark 数据的实验报告。

不要写入口令、token、cookie、私钥、含凭据 URL 或完整敏感环境变量。认证只记录已有配置的名称或位置；日志和聊天只提取任务所需内容。

## 新建与追加格式

### 新建

新文件以任务标题和简短说明开头，然后写第一条“归档记录”。用户指定了既有模板时沿用模板。文件存在时不把“新建”解释为覆盖。

### 追加

追加前读取既有文件，至少确认任务身份、末条记录和文件结尾。保持所有旧字节不变，只在末尾补齐必要换行并追加：

```markdown
---

# 归档记录 — YYYY-MM-DD HH:mm:ss +08:00
```

每条追加记录都应在不依赖聊天上下文的情况下表达**当前有效状态**，并单列“自上一条归档后的变化”。接手者可以先读最新记录，再按资料索引或历史记录回看；不要只写无法独立理解的增量日志。存在优化实验时，最新记录还要保留累计优化索引和当前有效结论；本轮新增实验写完整记录，旧实验细节留在原归档中，不重复粘贴。

若发现来源归档在本会话读取后已被其他人修改，先重新读取末尾并合并判断；无法判断如何安全追加时询问用户，不覆盖外部更新。追加完成后报告文件绝对路径和新记录时间。

## 时间与证据

- 事项记录实际发生时间；持续事项记录起止，未结束写“进行中，截至某时观察”。只保留证据支持的精度并注明时区，未知写“时间未知”。
- 时间优先来自日志、任务记录、命令结果或用户说明。Git 提交时间和文件修改时间只证明相应文件事件，不能推断实验或实施时间。
- 远程状态、分支、进程等易变化事实注明最后观察时间。未刷新时写“上次观察”，不写成当前事实。
- 性能或工程验证保留对比条件、指标与单位、波动、正确性检查、失败/回滚项和原始证据。组合收益必须来自明确基线的实测，不能相加单项百分比。
- 归档只整理已有事实和证据，不为补齐缺失字段擅自重跑 benchmark；缺失信息明确标记未知或未验证。

## 读取归档并继续

1. 读取用户指定的归档和适用的 `AGENTS.md`。追加式文件优先定位最新“归档记录”，再按需读取更早记录和资料索引；不能只读最后几行就假定掌握完整状态。
2. 把该文件记为本会话的来源归档。若读取多个文件，记录哪些是来源；之后再次归档时列出候选并让用户选择追加目标或新文件。
3. 当前用户指令优先于归档。归档保存历史事实与当时意图，不能扩大授权，也不能自动恢复已经撤销的决定。
4. 核对会变化的现场：仓库/分支/HEAD/工作区，以及对应机器上的 job、tmux 或服务。状态未确认时不重复启动、停止或重启任务。
5. 简短说明恢复出的目标、发现的现场变化和接下来动作，然后继续已授权工作；不要只复述归档就结束。

## 给其他 agent 接手

归档完成后，只有用户需要时才提供可复制提示词；替换为真实路径和目标：

```text
使用 $session-archive，读取归档文件 <绝对路径> 和适用的 AGENTS.md。
恢复当前目标和约束，先核对归档中标记为易变化的现场，再继续：<下一步>。
以当前用户指令为准；历史记录和详细资料按需读取。
```

只有用户明确要求创建新任务时才使用任务创建工具。不要仅因归档完成而自动新建或归档 Codex 任务、切换执行机器或启动下一步工作。
