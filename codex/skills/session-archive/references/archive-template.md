# 归档记录结构

按实际信息选用以下章节，不相关部分省略，未知事实明确标记，不保留尖括号占位符。默认使用段落和列表；用户要求表格原始 Markdown 时，用代码块输出表格。

新建文件可先写 `# 任务名称：会话归档`。新建和追加的每条记录均使用以下结构：

```markdown
# 归档记录 — <日期、时间、时区>

- 任务：<稳定、简短的名称>
- 源任务：<可获取的任务 ID/链接，否则注明未获取>
- 工作位置：<本地主机/远程机器和绝对路径>
- 记录范围：<当前会话，或从哪条来源归档至本次归档>

## 目标与约束
- 当前目标、完成标准、范围。
- 最新修正、仍有效的明确授权和限制；待批准事项单列。

## 当前状态
- 已完成：<事项实际时间；成果和位置>
- 已验证：<验证时间；对象/版本、方法、结果、证据>
- 未验证：<尚未核实的部分及原因>
- 进行中或阻塞：<开始时间、最后观察时间、原因和解除条件>

## 自上一条归档后的变化
- <新增完成项、决策、验证、失败尝试或现场变化；首条记录可省略>

## 关键决策与已排除方案
- <决策及原因和依据；明确已采纳还是建议>
- <失败尝试、失败条件和证据，避免重复尝试>
- <被取代的旧结论及当前有效结论>

## 代码、数据与运行现场
- <仓库绝对路径、分支、HEAD、未提交改动及归属>
- <数据来源、筛选范围、单位、统计口径和输出路径；不适用则省略>
- <机器、连接方式、工作目录、进程/job/tmux、端口、日志>
- <易变化事实的最后观察时间；当前已核实或未刷新>

## 优化实验索引
- <仅在存在推理优化、性能调优或工程实验时保留；按 OPT 编号概括改动、当前结论、关键实测结果和去向>
- <本轮新增、复测或结论变化的 EXP 编号，以及它们关联的 OPT>

## 本轮优化实验明细
- <按 EXP 编号逐项记录测试改动、基线、环境和负载、实测数据、有效性、工程验证、去向与证据；没有本轮实验时省略>

## 其他验证结果
- <不属于优化实验的正确性、精度、稳定性或兼容性验证及未覆盖项>
- <验证对象/版本、方法、结果和证据位置>

## 下一步
1. <第一步：对象、位置、动作、预期判据>
2. <后续关键动作和依赖>
- 待用户决定：<仅列阻碍推进的实质选择；没有则省略>

## 资料索引
- <路径或链接>：<内容、用途、必要时版本/时间；远程路径标明机器>
```

每条记录应是当前状态快照，能让只读最新记录的人理解任务；历史细节仍保留在更早记录中。长篇实验日志、生成物和已有报告只做索引，不复制进归档。没有优化实验时省略“优化实验索引”，不要为了套模板虚构实验。
