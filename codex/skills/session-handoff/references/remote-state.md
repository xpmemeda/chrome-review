# 远程任务现场

每个仍相关的机器或长任务保存以下已知字段，没有的信息标记未知：

- 身份：机器别称或 IPv6、所属网络集群、连接方式。
- 连接：SSH 别称，或 remote-agent URL 及本地客户端绝对路径。不得包含认证秘密。
- 文件：远程仓库/分支/HEAD、工作目录、模型路径、输入数据和输出/日志绝对路径。相同路径在不同机器上视为不同资源。
- 进程：remote-agent `start` 返回的原始 job ID；或 tmux session/window、服务端口；已知 PID 连同启动时间记录，避免仅靠可复用 PID 辨认进程。
- 状态：任务用途、启动命令或配置位置、最后一次状态、观察时间、是否仍需保留。命令中有凭据时只保存脱敏说明。
- 管理：状态/日志查询方式，必要时记录停止方式但标记“仅在需要且已获授权时执行”。交接不隐含清理进程的授权。

接手时遵守当前 `AGENTS.md` 的连接和代理规范：别称通过 SSH；IPv6 通过 remote-agent，先检查 health。连接失败如规范要求终止则停止并报告，不切换另一种未经验证的连接方案。需要联网时在同一远程 shell 设置对应集群代理；不把旧 shell 的环境视为持久配置。

进程管理必须使用“目标机器 + 原始 job ID”或“目标机器 + tmux 标识”，不能把另一台机器或另一轮实验的 ID 混用。记录可用的查询方法；客户端参数不确定时先查实际帮助，不虚构可执行命令。

远程不可访问时，保留上次观察和时间，明确当前状态未确认，不写“仍在运行”或“已完成”。不要为交接自动安装 agent、部署服务、复制模型或重新发起压测。
