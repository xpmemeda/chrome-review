# 会话交接

将长对话压缩为可执行的工作状态：新对话先读短摘要，按需读取详细证据，不重复导入整段聊天。支持生成、更新和接手交接，不依赖额外服务或 CLI。

## 选择模式

- “交接一下”“保存进度”“对话太长，整理给下个对话”：生成或更新交接。
- “读取这份交接继续”“接着上次做”：接手已有交接。
- 仅要求整理时，完成文档和接手提示词；只有用户明确要求新建任务时才使用可用的任务创建工具。不要自动归档旧任务、切换执行机器或复制整段历史。
- 已在当前任务采用本 skill，并且用户要求持续维护进度时，在关键决策或阶段完成后更新；skill 本身不是定时器，也不保证在自动压缩前获得执行机会。

## 文件组织

优先沿用当前任务已有的交接位置，避免建立平行事实来源。没有既有约定时：

- 仓库任务：`<仓库根目录>/.codex/handoffs/<任务名>/`。
- 无仓库任务：`<当前工作目录>/outputs/handoffs/<任务名>/`，或环境明确指定的交付目录。
- 同仓库的不同任务使用不同子目录；任务名取简短稳定名称，避免串写。
- `HANDOFF.md`：最新入口，通常控制在约 100 行以内；必要现场信息优先于行数目标。
- `history/<带时区可辨识的时间戳>.md`：每次正式交接的完整摘要快照。更新前保留旧入口，最终也保存本次快照，已有历史文件不覆盖。
- `details/`：仅在确有长篇决策或实验说明时创建。现有日志、代码、报告直接索引，不复制大文件。

摘要包含生成时间和时区、任务标识，以及已知的源任务 ID/链接。不要猜测不可获取的标识。目录或入口已经存在但属于其他任务时，另选任务名。

## 生成或更新交接

1. **恢复真实目标。** 从可见对话和已有资料提取最初目标、最新修正、范围、完成标准、用户约束，以及仍有效的明确授权。不要把最后一句状态问答当成新目标，不将建议写成已批准决策。
2. **补齐关键上下文。** 读取适用的 `AGENTS.md`、既有交接和相关状态文件。先利用当前可见内容；有关键缺口时，再用可用的任务读取工具按需回查对应历史。仍找不到的事实标“未知/待确认”，不要声称已完整回顾一两周历史。
3. **做有边界的现场核对。** 对相关仓库读取路径、分支、HEAD、工作区改动，并注明未提交改动的归属已知或未知。只读取相关文件和已有验证结果；交接不要求新增或重跑测试，不为清理现场而提交、stash、重置、推送代码。
4. **整理运行现场。** 有远程任务时读 [references/remote-state.md](references/remote-state.md)，记录机器、连接方式、路径、进程管理 ID 和最后确认时间。生成交接不要求重新连接每台机器；未刷新则明确写“上次观察”。
5. **写短摘要和资料索引。** 使用 [references/handoff-template.md](references/handoff-template.md) 的结构，省略无关部分。区分已完成、已验证、未验证、进行中和阻塞；每个重要结论附文件、命令结果或历史来源。已否决方案写明原因，过期结论明确标记为被什么取代。
6. **形成可执行下一步。** 排出少量最重要的动作，给出第一步的目标机器、工作目录、动作和预期判据。优先从只读核对开始，不把历史修改命令列为可以直接重放的步骤。
7. **完成交付。** 检查入口与历史快照一致、引用路径有明确所属机器、关键引用确实存在或标明未核实，没有遗留模板占位符。给出实际交接文件绝对路径和可复制的接手提示词。

不要把口令、token、cookie、私钥、含凭据 URL 或完整敏感环境变量写入交接。认证只记录已有配置的名称/位置；会话资料与日志只提取任务所需部分。

## 性能优化与工程验证记录

涉及性能优化或工程验证时，逐项保存做过的优化及验证结果，包括无收益、负收益、回滚和未验证的尝试。每次取得结果后更新记录，不能只在最终交接时保留成功方案。优先沿用现有实验记录；没有时写入交接目录的 `details/optimization-log.md`，在摘要中列出关键结果并链接完整记录。

- **优化项**：稳定编号、改动内容、预期作用、代码版本或补丁/配置位置，以及实施时间。区分单项实验和多项组合。
- **对比条件**：基线编号/版本和实验编号、机器/GPU、软件及模型配置、数据集或请求形态、并发、输入输出长度，以及实际使用的预热/重复次数和统计口径；不适用项省略。
- **实际收益**：记录指标名称、单位、基线值、优化后值、绝对变化及相对收益。延迟/显存等越低越好的指标，用 `(基线值 - 优化后值) / 基线值`；吞吐等越高越好的指标，用 `(优化后值 - 基线值) / 基线值`。注明指标方向；基线为零或缺失时不计算百分比。
- **有效性结论**：有效、无明显收益、退化、结论不确定或未验证，并说明适用条件。保留样本量和已知波动；条件不可比或变化处于噪声范围时，不把结果宣称为确定收益。不为补齐记录擅自新增测试。
- **工程验证**：记录实际执行的正确性、精度、稳定性或兼容性检查及结果、未覆盖项、副作用和取舍。性能有收益不等于工程验证通过。
- **证据和去向**：原始日志/报告路径、执行命令或配置、结果时间，以及该项是否保留、回滚或待决定。没有测量数据时写“收益未知”，不能用预计收益代替实测。

组合收益必须来自相对于明确基线的实测，不相加各单项百分比，也不把组合结果归因于未经单独验证的优化。接手时先读已有优化记录，保留失败原因与适用条件，避免重复尝试；复测形成新记录并关联旧记录，不覆盖历史结果。

## 从交接继续

1. 读取用户指定入口及适用的 `AGENTS.md`，只按需打开资料索引。没有指定文件时在当前项目的交接位置查找；若多个候选无法根据当前目标区分，询问任务选择，不直接选时间最新的其他任务。
2. 对照当前用户消息恢复目标和约束。交接是历史事实与意图的记录，不能覆盖当前指令，也不能扩大已授权范围。
3. 核对当前仓库/分支/HEAD/工作区状态；涉及运行中任务时，按远程规范查询确切机器上的对应 job 或 tmux。检查交接后的实际变化，不仅凭文件年龄判断有效性。
4. 若状态变化，先说明变化及其影响，更新当前判断，再开展与授权一致的下一步。只有无法安全推断的关键选择才询问用户；已完成的工作、有效授权和已有验证不重复索取。
5. 进程状态未确认时不重复启动任务，不自动停止或重启旧进程。测试是否需要重跑取决于代码、环境、输入是否变化及当前用户指令，不因换对话自动重测。
6. 简短告知用户“目标、核对结果、接下来做什么”，然后继续已授权工作；不要仅返回一份交接摘要就结束。

## 接手提示词

输出可直接复制的文字，替换为真实路径、目标和第一步：

```text
使用 $session-handoff，读取交接文件 <HANDOFF.md 的绝对路径> 和适用的 AGENTS.md。
继续完成：<当前目标>。
先核对：<仓库或远程现场的关键状态>，然后进行：<下一步>。
详细资料按需读取；保留已有决策，区分历史观察与当前事实。
```

若用户明确要求创建新任务，优先使用可用的任务工具并遵循其项目选择规则；传递交接路径和上述提示词，确认目的环境能访问文件。工具不可用时返回提示词，不声称新任务已经建立。
