# Grafana 看板编辑

在用户指定看板上完成修改并保存，保留无关查询、筛选变量和用户手动布局。仅询问会影响统计口径且无法从上下文判断的事项；用户已要求修改时，直接完成授权范围内的保存。

## 入口与资料

- 先查找适用的连接器、API 或 CLI；没有可用能力时，使用当前可用的 Browser skill，并遵守其浏览器选择、文档读取和访问方式。不要绕过登录或读取会话凭证。
- 通过浏览器编辑时，读 [references/browser-editing.md](references/browser-editing.md)。具体调用以当前 Browser 文档为准，不依赖上次对话的变量、标签页或工具名称。
- 编辑「Omni-Agent 主模型监控」或复用 seed.llmserver 指标时，读 [references/omni-agent-metrics.md](references/omni-agent-metrics.md)。其中 UID 和指标仅作定位线索，现场配置优先。

## 编辑流程

1. 确认 UID、目标 panel、PSM 和筛选范围。从服务器读取最新 JSON，递归检查顶层 `panels` 及折叠 row 的 `panels`。标题可能重命名，结合 ID、查询和截图识别目标。
2. 将修改前 JSON 备份到当前任务目录的 `grafana-backups/<UID>-<时间>.json`，记录版本。不要把可能过期的完整看板写入 Skill；仅备份通过已授权界面或接口读出的配置，不附带认证信息。
3. 只修改目标字段。保留其他 panel、数据源、变量默认值、筛选条件、时间范围和用户布局。新 ID 从所有嵌套 panel 的最大 ID 后分配，不能只检查顶层。
4. 核对统计口径，再改查询和对应标题、图例、说明。保存前审阅配置差异；若出现并发版本冲突，重新读取并重做目标改动，不强制覆盖他人修改。结果不明时先读服务器确认，不盲目重试保存。
5. 保存后从新页面或接口重新读取，确认配置持久化。用用户 PSM 和时间范围验证标题、曲线数量、图例数值及报错；区分数据加载中、空序列和零。没有数据时如实说明，不能仅凭成功保存宣称指标可用。
6. 简洁交付修改内容、验证结果和看板链接。有明确数据口径变化时说明，例如“从单实例均值改为所有实例总和”。

## 聚合与展示

- 跨实例总量用空间 `sum`；实例/进程均值用空间 `avg`。时间降采样独立设置：速率、gauge 通常用 `avg`，每个上报周期的计数通常用 `sum`。先确认指标语义，不能仅凭名称套用。
- 不区分 IDC/host/process_id：取消相应分组并更新 alias；保留筛选条件。“不分 IDC 展示”不等于无视用户选中的 dc。
- “Prefill 和 Decode 两条线”：每个角色独立查询和聚合，移除无关角色查询，核对隐藏查询及额外分组是否还会产生多条线。
- 对 `.avg` 序列再 `avg` 通常是上报序列的均值，不是请求加权均值。请求加权口径需核对匹配的 sum/count；P99 不能通过平均各实例 P99 得到全局 P99。
- 图例 `Mean` 是返回曲线在所选时间范围的均值；`Total`/`sum` 是返回点的和，只有计数及降采样口径正确时才可解释为累计次数。不能把 QPS 点直接相加称为请求数。
- `No data` 不当成 0，不为美观擅自补零或连断点。比率分母为零或缺失时保留未定义。
- `fieldConfig.defaults.decimals=2` 控制两位小数；`unit=short` 仍会显示 K/M。如用户要完整数字，另选不缩写的单位。
- 固定图例顺序应核对排序配置和实际呈现，不能只交换查询顺序就宣称已固定。

## 布局

Grafana 标准网格一行 24 格，半行 `gridPos.w=12`，三列 `w=8`。同排 panel 的 y 相同，x 分别从 0、12 或 0、8、16 开始。插入整行时只移动受影响位置，检查重叠和 row 归属。折叠 row 中的 panel 可能嵌套存储，禁止为方便编辑而丢掉整组。
